# Gemma 4 E4B — локальный чат-сервер на CPU

Веб-чат и CLI-клиент для локального запуска модели **Gemma 4 E4B** (GGUF) через
[`llama-cpp-python`](https://github.com/abetlen/llama-cpp-python). Работает полностью
на CPU, без GPU. Поддерживает **родной режим раздумий** (reasoning) модели и контекст
до 8K токенов.

Собрано и проверено в облачном контейнере: Intel Xeon (4 ядра, AVX-512/AMX), 16 ГБ RAM,
Ubuntu 24.04. Скорость генерации на Q4 — около **4–5 токенов/сек**.

## Что внутри

| Файл | Назначение |
|------|-----------|
| `server.py` | FastAPI-сервер: грузит GGUF, отдаёт веб-интерфейс и потоковый API с раздумьями |
| `index.html` | Тёмный веб-чат: стрим токенов, сворачиваемый блок раздумий, счётчик tok/s |
| `chat_cli.py` | Консольный клиент к серверу (с памятью диалога), раздельно печатает мысли и ответ |
| `download_model.sh` | Скачивает нужный квант модели в `models/` |
| `requirements.txt` | Зависимости Python |

## Требования

- Python 3.10+
- Компилятор C/C++ (gcc/clang) и CMake — `llama-cpp-python` собирается из исходников
- ~5 ГБ на диске под модель Q4 и несколько ГБ RAM

## Установка

```bash
cd gemma-server

# 1) окружение и зависимости (сборка займёт несколько минут)
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
# для нативной оптимизации под свой CPU:
#   CMAKE_ARGS="-DGGML_NATIVE=ON" pip install -r requirements.txt

# 2) скачать модель (по умолчанию Q4_K_M, ~4.7 ГБ)
bash download_model.sh
# или другой квант: bash download_model.sh Q6_K
```

Выбор кванта под объём RAM:

| Квант | Файл | RAM в работе | Комментарий |
|-------|------|--------------|-------------|
| `Q4_K_M` | ~4.7 ГБ | ~6 ГБ | по умолчанию, быстрый |
| `Q5_K_M` | ~5.1 ГБ | ~7 ГБ | чуть качественнее |
| `Q6_K` | ~6.6 ГБ | ~8 ГБ | почти без потерь |
| `Q8_0` | ~7.6 ГБ | ~9 ГБ | максимум качества, медленнее |

## Запуск

```bash
source venv/bin/activate
python server.py
# сервер поднимется на http://0.0.0.0:8080
```

Настройки через переменные окружения:

```bash
N_CTX=8192 N_THREADS=4 PORT=8080 python server.py
```

### Веб-интерфейс
Открой `http://<адрес-сервера>:8080` в браузере. Есть поле ввода, стрим ответа,
сворачиваемый блок «раздумья», ползунок temperature, лимит токенов и галочка раздумий.

### Консольный клиент
```bash
python chat_cli.py "Твой вопрос"        # с раздумьями (по умолчанию)
python chat_cli.py --nothink "Вопрос"   # без раздумий, сразу ответ
python chat_cli.py --reset              # очистить историю диалога
```

## API

`POST /api/chat` — потоковый ответ в формате Server-Sent Events.

Тело запроса:
```json
{
  "messages": [{"role": "user", "content": "Привет"}],
  "temperature": 0.7,
  "max_tokens": 2048,
  "think": true
}
```

События SSE (`data: {...}`):
- `{"think": "..."}` — кусочек раздумий
- `{"t": "..."}` — кусочек финального ответа
- `{"done": true, "tokens": N, "tok_per_s": X, "ttft_s": Y}` — конец + статистика
- `{"error": "..."}` — ошибка

`GET /api/info` — информация о модели и настройках.

## Как устроены раздумья

У Gemma 4 режим раздумий включается параметром `enable_thinking` в шаблоне чата.
Сервер рендерит промпт вручную через `Jinja2ChatFormatter(..., enable_thinking=True)`,
модель пишет рассуждения в канал `<|channel>thought ... <channel|>`, а сервер на лету
разделяет поток на «мысли» и «ответ».
