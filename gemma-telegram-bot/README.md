# Telegram-бот на локальной Gemma 4 (CPU)

Телеграм-бот, который отвечает через локальную модель **Gemma 4 E4B** (GGUF),
запущенную на CPU-сервере, и **видит картинки** (родная мультимодальность Gemma 4).
Long-polling — **входящие порты не нужны**. Удобно общаться со своей моделью с
телефона из любого места.

## Возможности

- **Ответ в прямом эфире** — сообщение обновляется каждые ~4 с, видно, как модель
  думает и печатает (с курсором ▍)
- **⛔ Стоп** — кнопка под ответом прерывает генерацию на лету (генерация идёт в
  отдельном потоке, бот продолжает слушать)
- **🖼 Фото** — пришли картинку (с подписью-вопросом или без) — модель опишет её или
  ответит на вопрос; работает и для картинок, отправленных файлом
- **📋 Код с копированием** — блоки кода оформляются так, что Telegram показывает
  кнопку «копировать»
- **🤔 Раздумья** `/think` — модель рассуждает перед ответом (медленнее, но умнее);
  мысли показываются отдельно, для них выделен запас токенов
- **📖 Статистика скорости** — статус чтения контекста и ток/с после ответа
- **Настройки с сохранением** (`chat_settings.json`): контекст и лимит ответа через
  inline-кнопки
- **Управление моделью из чата** — загрузить / выгрузить из RAM (~7–9 ГБ)
- Меню-кнопки снизу и автоподсказки при вводе «/»

## Команды

| Команда | Действие |
|---|---|
| `/think` | вкл/выкл режим раздумий |
| `/context` | размер контекста: 2048 / 4096 / 8192 / 16384 (смена перезагружает модель) |
| `/limit` | лимит длины ответа: 256 / 512 / 1024 / 2048 / 4096 |
| `/model` | загрузить / выгрузить модель (также `/load`, `/unload`) |
| `/reset` | сбросить диалог |
| `/status` | текущие настройки |
| `/help` | помощь |
| текст / фото | вопрос к модели |

Контекст — общий (модель одна в памяти); лимит ответа, раздумья и температура — у
каждого пользователя свои. Всё сохраняется и переживает перезапуск.

Значения по умолчанию: контекст 8192, лимит ответа 1024, раздумья выключены.

## Установка

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt     # llama-cpp-python (собирается из исходников)

bash download_models.sh             # Gemma 4 E4B Q4_K_M (~4.7 ГБ) + mmproj (~0.9 ГБ)
```

`mmproj-F16.gguf` — визуальный проектор («глаза»). Без него бот отвечает на текст,
но фото не принимает. Файлы лежат в `./models/`.

## Токен

Получи токен у [@BotFather](https://t.me/BotFather) (`/newbot`) и положи его в файл
`bot_token.txt` рядом со скриптом (см. `bot_token.txt.example`), либо задай
переменную окружения `TG_TOKEN`.

> ⚠️ `bot_token.txt` в репозиторий не коммитится (см. `.gitignore`). Токен — пароль
> от бота, не публикуй его. Если утёк — отзови через @BotFather.

## Запуск

```bash
source venv/bin/activate
python telegram_bot.py
```

Модель стартует выключенной (мгновенный старт, память свободна). Напиши боту
сообщение или `/model` — он загрузит Gemma и начнёт отвечать.

Скорость на 4 ядрах CPU: чтение промпта десятки ток/с, генерация ~4–5 ток/с. Ответ с
раздумьями и большим лимитом может идти минуты — для этого и есть «Стоп».

## Автоперезапуск

Если бот упал — его поднимет сторож из `../ops/watchdog.sh`:

```bash
nohup bash ../ops/watchdog.sh >/dev/null 2>&1 &
```

Сторож следит и за ботом-пультом (`server-control-bot`), если он есть в ветке. После
перезагрузки машины сам не стартует — запусти его снова или повесь на systemd/cron.

## Заметки

- Для зрения используется `Gemma4ChatHandler` из `llama-cpp-python` (нужна версия с
  его поддержкой, проверено на 0.3.37); обработка идёт на CPU.
- Картинка обрабатывается разово и в память диалога не попадает: чтобы задать новый
  вопрос по тому же фото, пришли его ещё раз.
- Файл `gemma_state.txt` бот пишет для пульта (`загружена / выгружена` модель).
